# 从本地模型启动我们自己的推理引擎

Flow Inference 是第七部分新的独立成果。它不是旧实战目录中的 vLLM 插件，也不是可视化平台的改名。先用你现有的 Qwen2.5-0.5B-Instruct 跑通，再逐步扩大模型和硬件范围。

## 先知道哪些模型能运行

当前执行的是稠密 Llama/Qwen2/Qwen2.5 的全注意力、默认 RoPE 文本模型。具体真实权重已验证 Qwen2.5-0.5B-Instruct。不要把 GLM53、Gemma4、MiniMax、多模态或 MoE 的目录填进去期待自动适配：它们会被架构检查拒绝。以后每增加一个架构，都要有模型实现、权重映射、KV语义和参考结果验证。

你的 Mac 可以用 MPS 执行。默认 FP32 是当前通过严格 token 对照的路径，不是最省内存的路径；FP16 是显式实验，已有测试出现长输出 token 差异。CUDA 的 Triton 内核仍需在租用 GPU 后验证。

## 创建独立环境

如果准备租第一台 H100，先阅读 [CPU 预下载与 H100 首测](H100_FIRST_RUN.md)：它包含持久盘准备、固定版本下载、4小时预算、命令日志和断点续跑。不要直接在计费 GPU 上下载全部大模型。

从项目目录运行：

```bash
conda env create -f environment.yml
conda activate flow-inference
flow-inference doctor
```

环境放在你使用的 Miniforge/Miniconda 管理目录里。命令会安装项目依赖，不会修改原来的 `workbench-mlx` 或 `llm-dev-mac`。若只想先查看源码，不必创建环境。安装需要联网，网络与代理由你当前的包管理器配置决定；运行引擎本身不会自动下载模型。

`doctor` 只检查 Python、PyTorch、CUDA/MPS 可用性。若 `mps_built=true` 而 `mps_available=false`，说明当前执行环境看不到 Apple GPU，不应把 CPU 执行结果标成 GPU 结果。

## 选择真正的权重目录

目录里至少有 `config.json`、tokenizer 文件、`model.safetensors` 或其分片索引。HF 缓存应该选择 `snapshots/<revision>`，不是上层 `models--...`。

```bash
flow-inference inspect /absolute/path/to/model
```

这一步不加载大权重，只检查架构并计算 KV 页池大小。它不会替你分配GPU，也不会把一个 KV 数字当成完整显存需求。

默认每个池有256块、每块16个 token，共4096个物理 token 槽位。多个请求和缓存条目分享这些槽位。`--max-context 2048` 是单请求 prompt 加最多输出的上限，不是“立即分配2048个生成 token”。准入时会预留该请求声明的完整上限，避免中途无页。

## 先直接生成一句话

```bash
flow-inference generate /absolute/path/to/model \
  --device mps --dtype float32 \
  --prompt '用三句话解释大模型推理中的 KV Cache。' \
  --max-tokens 96 --log runs/first-answer.jsonl
```

屏幕会打印模型回答，标准错误输出包含 usage 和耗时。这里不调用任何云端服务。第一次执行可能有后端初始化成本，不能拿首次启动时间直接代表稳态速度。

如果内存不足，先减小模型或 KV 池、上下文和输出预算；不要以为减少 `max_tokens` 就能减少权重常驻内存。FP16可能减少权重和缓存容量，但需要通过相同精度的质量检查。

## 再启动持续服务

```bash
flow-inference serve /absolute/path/to/model \
  --device mps --dtype float32 --port 8010 \
  --max-context 2048 --max-active 4 \
  --prefill-chunk 256 --target-step-ms 50 \
  --served-model-name flow-model --log runs/server.jsonl
```

模型加载和一次真实 warmup 完成后才开放服务。另开终端：

```bash
curl --noproxy '*' http://127.0.0.1:8010/health
curl --noproxy '*' http://127.0.0.1:8010/v1/models
```

`health` 返回 `ready=true` 才表示引擎工作线程可以服务，不只是端口存在。发生模型执行异常后，健康检查返回503，错误不会伪装成空回答。

发送请求：

```bash
curl --noproxy '*' -N http://127.0.0.1:8010/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"flow-model","messages":[{"role":"user","content":"为什么要对推理进行加速？"}],"max_tokens":96,"temperature":0,"stream":true}'
```

`temperature=0` 是贪心。温度大于0采用请求独立随机种子进行完整 softmax 采样，不等于支持 top-p/top-k。未实现的参数会报422，不会无声忽略。

API 是文本子集：暂不接图片、音频、视频、工具调用。服务端 usage 的 completion_tokens 包括生成的特殊 token；显示文本隐藏特殊 token，所以文本长度不能替代 token 数。

## 在已有可视化平台中连接

用平台已有的外部服务登记方式填：

```text
API base URL: http://127.0.0.1:8010/v1
Model: flow-model
```

本次没有修改 Model Workbench 的引擎下拉列表。接入外部服务和新增原生部署适配器是两回事；后续平台适配器应负责启动、停止、日志定位和兼容性检查，不能仅填一个名字。

本服务仅绑定本机回环地址。云端运行时，在你的 Mac 上建立隧道：

```bash
ssh -N -L 8010:127.0.0.1:8010 your-gpu-host
```

本地访问8010经SSH到远端8010。不要把无鉴权预览服务直接暴露到公网。

## 怎样切换和卸载模型

在服务终端按 Ctrl+C。引擎停止接入、等待当前 kernel 返回、结束请求并清理引用；Python进程退出后释放模型内存。换模型目录重新运行 `serve`。当前没有热卸载 HTTP API，不要在旧进程未结束时重复启动同端口。

## 怎样打开和验证优化项

先保存不启用投机的基线。然后加入：

```bash
--draft-tokens 4 --draft-window 512
```

它只针对单个活跃贪心请求，在已确认历史中查找可能重复的后续；无命中、只剩一个输出位置、多请求或随机采样时回到正常解码。不需要额外草稿权重。复制和局部代码编辑可能有用，开放问题可能更慢。

`--unfused` 用来关闭默认 QKV/gate-up 合并，做同模型消融。`--no-prefix-cache` 用来关闭前缀复用，区分缓存收益与内核收益。CUDA 的 `--attention triton` 不会在 Mac 上运行，且必须先执行 CUDA 测试和真实模型验证。

## 日志怎么看

```bash
flow-inference replay runs/server.jsonl
curl --noproxy '*' http://127.0.0.1:8010/metrics
```

重点看 `admit.reused_tokens`、`step.phase`、`step.elapsed_ms`、`reserved_blocks`、`free_blocks`、`draft_accepted` 和 `finish.usage`。这些能回答“复用了什么、这一轮计算了什么、为什么等待、何时回收”。详细变量与公式在 [架构推演](ARCHITECTURE.md)。

日志默认不包含私人问题和回答。若执行 benchmark，结果文件会保存测试回答以便核对质量，请使用非敏感测试集。日志按容量轮换；长期实验应主动归档，不能把轮换文件当永久历史库。

## 怎样证明是正确和更快

先跑 `tools/validate_model.py`，检查真实模型 logits、冷/热前缀、单请求/批请求和固定长度 token IDs。然后按照 [对照协议](BENCHMARKS.md) 与 vLLM、SGLang 对比。开关优化后输出不一致时先停止提速结论，查精度、采样规则、EOS、模板和缓存语义。

当前成果是已能执行真实模型的独立研究引擎，不是已经胜出所有工业框架的成品。后续研究要把吞吐、首 token、单流延迟、容量和可靠性分别验证，而不是选一个最有利的数字。
